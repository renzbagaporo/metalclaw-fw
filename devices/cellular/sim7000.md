# sim7000

A SIMCom SIM7000 series LTE-M/NB-IoT/GPRS modem on UART, with its PWRKEY.
The harness answers the AT commands of the SIM7000 Series AT Command Manual
V1.06 that TinyGSM's two SIM7000 clients send, so the board under test can
boot the modem, attach, bring up the data bearer either of the module's two
ways, open TCP and UDP sockets, read GNSS fixes, send SMS and sync the
time, against the package's [fake network](README.md#the-fake-network).
There is no Zephyr driver for the part. The behaviour is TinyGSM's
`TINY_GSM_MODEM_SIM7000` (the SIM800-style CIP stack, no TLS) and
`TINY_GSM_MODEM_SIM7000SSL` (the CNACT/CA stack), and one model serves both.

`sim7000.c` holds the descriptors, the config and the model's own commands
and URCs (the bearer, GNSS, location, NTP, USSD); `sim7000_cip.c` is the
CIP stack and the connection bookkeeping; `sim7000_ca.c` is the `CA*`
commands. The engine, the standard commands, SMS and the network are the
package's ([README](README.md)). The model has all four parts: modem,
network, GNSS and SMS, so its properties and regions are every one the
README lists.

## Attaching

The UART binding advertises the module's fixed rate, 115200 baud 8N1. On
fixture 1 the crossed pair is GP0/GP1 and the DUT's GP6 drives the
harness's GP6:

```python
import metalclaw
modem = metalclaw.attach("sim7000", "modem", uart=(0, 1), pwrkey=6)
modem.write_region("hosts", 0, b"vsh.pp.ua=192.0.2.80\nbroker.hivemq.com=192.0.2.18\n\0")
modem.write_region("file", 0, open("test_1k.bin", "rb").read())
modem.set(file_length=1024, latitude=31221946, longitude=121355565, fix=True, satellites=9)
modem.powered, modem.pdp, modem.connections, modem.bytes_down
modem.reset()
modem.detach()
```

`pdp` is true while any of the three bearer holders is up (see below),
`connections` counts successful `CIPSTART`s and `CAOPEN`s, `registration`
is the `+CEREG` stat, `boot_ms` defaults to 4500 and `power_cycles` counts
`RDY`s sent.

## Power and timing

| from | event | to |
| --- | --- | --- |
| off | PWRKEY low for 1 s (Ton) | booting |
| booting or on | PWRKEY low for 1.2 s (Toff) | `NORMAL POWER DOWN`, off |
| booting | `boot_ms` later | `RDY`, `+CFUN: 1`, `+CPIN: READY` (or `NOT INSERTED`, `SIM PIN`), `SMS Ready`; on |
| on | `AT+CPOWD=1` | `NORMAL POWER DOWN`, off (`AT+CPOWD=0`: off, silent) |
| on | `AT+CFUN=1,1` or `AT+CFUN=6` | `OK`, booting |

The times are the hardware design's (V1.07 tables 8 and 9): Ton at least 1 s,
Toff at least 1.2 s, the UART ready at least 4.5 s after the power-on issue.
`boot_ms` counts from the moment the press is accepted, so `RDY` comes 5.5 s
after the press starts. The baud rate survives a boot, as `AT+IPR` is saved
by the module. `SMS Ready` is not in the manual, but TinyGSM's `restart`
waits up to 30 s for it and re-runs its `init()` when it sees it.

After `CFUN=0` the module sends `+CPIN: NOT READY` after the `OK`; commands
sent during a `CFUN=1,1` reboot are ignored (the module is off the UART) and
the reboot starts with echo on.

Answers trail commands only where the manual shows them after the `OK`:
`+CNTP` and `+CUSD: 4` come 50 ms after the command. `+APP PDP` and the
connection results of `CIPSTART` follow the `OK` at once. Everything else
is answered from `on_rx`. Input waits while the output FIFO has less than 512
bytes free, room for the longest `AT+CIPSTATUS` list; a URC waits for 48.

## Commands

Test forms (`=?`) of the commands below answer `OK` or the manual's ranges.

| command | answer |
| --- | --- |
| `AT`, `ATE0`/`ATE1`, `ATZ`, `AT&F`, `AT&W` | `OK` |
| `ATV0`, `ATV1` | `OK`; `ATV0` turns to numeric result codes (`0\r`, `4\r`) and `ATV1` back |
| `ATI` | `SIM7000 R1351` (manual 2.2.5) |
| `AT+CGMI` | `SIMCOM_Ltd` |
| `AT+CGMM` | `SIMCOM_SIM7000G` |
| `AT+CGMR` | `Revision:1351B03SIM7000G` |
| `AT+CGSN`, `AT+GSN` | `862818040001234` |
| `AT+CIMI` | `001010123456789` (needs the SIM) |
| `AT+CCID` | `89882280666027595036`, no prefix (needs a SIM inserted) |
| `AT+CMEE=<n>`, `?` | 0, 1, 2 |
| `AT+IPR=<rate>`, `?` | 9600 to 921600; `OK`, then the switch |
| `AT+CFUN=<fun>[,<rst>]`, `?` | 0, 4, 5, 7 drop the network (`+CPIN: NOT READY`), 1 restores it (`+CPIN: READY`), `rst` 1 or `fun` 6 reboot |
| `AT+CPOWD=<n>` | see above |
| `AT+CLTS`, `AT+CBATCHK`, `AT+CSCLK`, `AT+CSMP`, `AT+CNMI`, `AT+CNTPCID`, `AT+CASSLCFG` | `OK` |
| `AT+CPIN?` | `+CPIN: READY` or `+CPIN: SIM PIN`; CME 10 without a SIM |
| `AT+CPIN=<pin>` | any PIN unlocks a PIN-locked SIM: `OK`, `+CPIN: READY` |
| `AT+CSQ` | `+CSQ: <rssi>,99`; `99,99` below CFUN 1 |
| `AT+CREG`, `AT+CGREG`, `AT+CEREG` `=<n>`, `?` | `+CEREG: <n>,<stat>`; with `n` set, a stat change sends `+CEREG: <stat>` (and the others) |
| `AT+CGATT?`, `=<0/1>` | attached: SIM ready, CFUN 1, stat 1 or 5, not detached by `CGATT=0` |
| `AT+COPS?` | `+COPS: 0,0,"Metalclaw",7`; `+COPS: 0` unregistered |
| `AT+CGDCONT=1,"IP","<apn>"`, `?` | the APN is stored |
| `AT+CGACT=<0/1>[,<cid>]`, `?` | context 1 only; `1` needs the attach (CME 30); `+CGACT: 1,<state>` |
| `AT+SAPBR=<cmd>,<cid>[,"<tag>","<value>"]` | see Bearers |
| `AT+CNCFG=<ip_type>[,"<apn>",...]`, `?` | the APN is stored |
| `AT+CNACT=<0/1/2>[,"<apn>"]`, `?` | see Bearers |
| `AT+CGNSPWR=<0/1>`, `?`; `AT+CGNSCOLD`, `WARM`, `HOT` | `OK` |
| `AT+CGNSINF` | see below |
| `AT+CLBS=<1/4>,<cid>` | attached: `+CLBS: 0,<lon>,<lat>,500[,yy/MM/dd,hh:mm:ss]`; `+CLBS: 3` otherwise |
| `AT+CUSD=<n>[,"<code>"]` | no USSD service: `OK`, then `+CUSD: 4` (manual 3.2.23); CME 30 unregistered |
| `AT+CMGF=<0/1>`, `?`; `AT+CSCS`, `?` | PDU mode at boot; `+CSCS: "IRA"`, any `CSCS` is accepted |
| `AT+CMGS="<num>"` (text), `AT+CMGS=<len>` (PDU) | `\r\n> `, the message up to Ctrl-Z, `+CMGS: <mr>` `OK`; ESC abandons with `OK` |
| `AT+CMGL=<stat>`, `AT+CMGD=<index>[,<flag>]` | as the SIM7080G page |
| `AT+CBC` | `+CBC: 0,<battery_percent>,<battery_mv>` |
| `AT+CCLK?`, `=` | `+CCLK: "yy/MM/dd,hh:mm:ss±zz"`, local time (`time` plus `timezone`); the write sets both |
| `AT+CNTP="<srv>"[,<tz>]`, `AT+CNTP` | `OK`, then `+CNTP: 1` while attached (the zone given becomes `timezone`), `+CNTP: 61` otherwise |

`+CGNSINF` has the 21 fields of the manual's table 15-1, which is what
TinyGSM parses. GNSS off it is `0` and twenty empty fields. On without a fix:
`1,0,<utc>`, five empty fields, fix mode `0`, five more, the satellites in
view, and six empty. With a fix: run 1, fix 1, UTC `yyyyMMddhhmmss.000`,
latitude and longitude with six decimals, altitude in metres with three,
speed in km/h with two, course with one, fix mode 1, an empty reserved
field, HDOP, PDOP and VDOP all equal to `hdop` with one decimal, an empty
reserved field, satellites in view and satellites used both `satellites`,
GLONASS satellites 0, an empty reserved field, the strongest C/N0 as 40,
and HPA and VPA of five times HDOP in metres.

`AT+CLBS` is not in the SIM7000 manual; TinyGSM's GSM location sends it and
takes the SIM7080G's answer, longitude first, so the model answers that
way with the GNSS position as the fake cell. `+CLBS` and `+CNTP` need the
attach but no bearer: TinyGSM's SIM7000SSL driver never opens SAPBR profile
1, which the commands refer to.

## Bearers

The module has three ways to hold its data bearer. The model keeps a holder
bit for each and the network's bearer (the `pdp` property) is up while any
is set.

| holder | up | down |
| --- | --- | --- |
| CIP stack | `AT+CIICR` | `AT+CIPSHUT` |
| SAPBR profile 1 | `AT+SAPBR=1,1` | `AT+SAPBR=0,1` |
| CNACT | `AT+CNACT=1[,"<apn>"]` | `AT+CNACT=0` |

`AT+SAPBR=3,1,"<tag>","<value>"` sets a parameter (`APN` is kept),
`=4,1,"<tag>"` reads one, `=2,1` is `+SAPBR: 1,<1 open, 3 closed>,"<ip>"`.
`=1,1` needs the attach (CME 30) and fails when the profile is open.

`AT+CNACT=1` answers `OK` and then `+APP PDP: ACTIVE`, with no context
number (manual 5.2.30; the SIM7080G's carries one). Without the attach the
URC is `+APP PDP: DEACTIVE`, the failure TinyGSM's retry loop looks for;
when already active it is CME 3. `AT+CNACT=0` answers `OK`, then at once
`+APP PDP: DEACTIVE` and `+CASTATE: <cid>,0` for each open CA connection;
inactive it is only `OK`. TinyGSM fails a `CNACT=1` on a late `DEACTIVE`,
so it is never late. `AT+CNACT?` is the single line
`+CNACT: <0/1>,"<ip>"`.

Losing the network (registration, CFUN, `CGATT=0`) takes every holder down at
once, each reporting in its own form, in this order: `+PDP: DEACT` (CIP),
`+APP PDP: DEACTIVE`, `+SAPBR 1: DEACT`; then a close URC for each open
connection. The CIP stack stays in `PDP DEACT` until `AT+CIPSHUT`.

## The CIP stack

Multi-IP mode with manual receive, as TinyGSM sets it: `CIPMUX=1`,
`CIPQSEND=1`, `CIPRXGET=1`. Eight connections, `<mux>` 0 to 7.

| command | answer |
| --- | --- |
| `AT+CIPSHUT` | `SHUT OK` (no `OK`) in any state: every CIP connection ends silently, the CIP bearer is released, state `IP INITIAL` |
| `AT+CIPMUX=<0/1>`, `?` | only in `IP INITIAL`, else `ERROR`; single-connection mode (0) is accepted and not modelled |
| `AT+CIPQSEND=<0/1>`, `?` | stored |
| `AT+CIPRXGET=1` | manual-receive mode on (the default is off and then no data URC is sent); modes 0 and 3 are `ERROR` |
| `AT+CSTT="<apn>","<user>","<pwd>"` | only in `IP INITIAL`, to `IP START`, else `ERROR` |
| `AT+CIICR` | only in `IP START` and attached, to `IP GPRSACT`, holding the bearer |
| `AT+CIFSR` | in `IP GPRSACT` or later: the bare address, **no `OK`**, state `IP STATUS`; else `ERROR` |
| `AT+CIFSR;E0` | the address, then ATE0 and its `OK`: `\r\n10.0.0.2\r\n\r\nOK\r\n` and echo off |
| `AT+CIPSTART=<n>,"TCP"/"UDP","<host>",<port>` | only in `IP STATUS`: `OK`, then `<n>, CONNECT OK`, or `<n>, CONNECT FAIL` (unknown host, nothing listens), or `<n>, ALREADY CONNECT` |
| `AT+CIPSEND=<n>,<len>` | `\r\n> `, exactly `len` (1..1460) bytes, then `DATA ACCEPT:<n>,<len>` with `CIPQSEND=1` or `<n>, SEND OK` with 0; no `OK`; `ERROR` when the 5 s pass first |
| `AT+CIPSEND=<n>` | the same ended by Ctrl-Z; ESC ends it with `OK`, the bytes before it are already sent |
| `AT+CIPCLOSE=<n>` | `<n>, CLOSE OK`; `ERROR` for a connection that was never opened or is closed |
| `AT+CIPSTATUS=<n>` | `+CIPSTATUS: <n>,0,"TCP","<ip>","<port>","<state>"`, the state quoted; `CONNECTED`, `CLOSED` (the server closed), or `INITIAL` with empty fields |
| `AT+CIPSTATUS` | `OK`, then `STATE: IP INITIAL/START/GPRSACT/STATUS` or `PDP DEACT` (`IP PROCESSING` in place of `IP STATUS` while a connection exists), and a `C: ...` line per connection |
| `AT+CIPRXGET=4,<n>` | `+CIPRXGET: 4,<n>,<bytes buffered>` |
| `AT+CIPRXGET=2,<n>,<len>` | `+CIPRXGET: 2,<n>,<k>,<rest>`, CR LF, `k` bytes, CR LF, `OK` |

`+CIPRXGET: 2` is TinyGSM's reading of the fields: the third is the number of
bytes that follow (at most `len`, at most what the FIFO can take) and the
fourth the bytes left in the buffer. The manual calls them `<reqlength>` and
`<cnflength>`; TinyGSM's comment (SIM7000.h:378-380) says the real module
sends the remainder, and `k` must equal what is sent. With nothing buffered
it is `2,<n>,0,0` and no data.

`+CIPRXGET: 1,<n>` is sent once, when a connection's buffer goes from empty
to non-empty. `<n>, CLOSED` is sent when the server closed, and only once
the DUT has read every byte, so the buffer query keeps working until then
and `CIPSTATUS=<n>` reports `CONNECTED` for as long as data is waiting.

## The CA stack

The CNACT stack's sockets, as TinyGSM's SIM7000SSL speaks them: two
connections, cid 0 and 1 (`CAOPEN` of another cid is result 3). TinyGSM
indexes its two sockets by every cid that `CASTATE?` and `CARECV?` name, so
the model has no more.

| command | answer |
| --- | --- |
| `AT+CACID=<cid>`, `?` | stored |
| `AT+CSSLCFG="sslversion",<ctx>,<v>` | stored; the other `CSSLCFG` forms are `OK` |
| `AT+CSSLCFG="ctxindex",<ctx>` | `+CSSLCFG: <ctx>,<sslversion>,0x0035,0,1,""`, then `OK` |
| `AT+CASSLCFG=<cid>,ssl,<0/1>` etc. | `OK`; `ssl`, `CACERT` and `protocol` unquoted and in any case |
| `AT+CAOPEN=<cid>,"<host>",<port>` | `+CAOPEN: <cid>,<result>`, then `OK`; the connection type is optional (`"TCP"`/`"UDP"` between cid and host), TCP without it: 0, 1 open or used by the CIP stack, 3 cid 2 or more, 4 bad parameter, 20 unknown host, 21 CNACT not active, 23 nothing listens |
| `AT+CAOPEN?` | `+CAOPEN: <cid>,"TCP"/"UDP","<a.b.c.d>",<port>` per open connection |
| `AT+CASEND=<cid>` | `+CASEND: 1460`, `OK` |
| `AT+CASEND=<cid>,<len>[,<ms>]` | `\r\n> `, exactly `len` (1..1460) bytes, then `OK` and after it `+CASEND: <cid>,0,<len>`; `ERROR` when `<ms>` (default 5000) passes first |
| `AT+CARECV=<cid>,<len>` | `+CARECV: <n>,<n bytes>` with **no cid**, CR LF, blank line, `OK`; `n` at least 1; CME 3 with nothing buffered |
| `AT+CARECV?` | `+CARECV: <cid>,<len>` per connection with data |
| `AT+CASTATE?` | `+CASTATE: <cid>,<1 open, 0 closed by the server>` per connection not yet `CACLOSE`d |
| `AT+CACLOSE=<cid>` | `OK`; CME 3 for a closed cid |

Both orders are the manual's: `OK` before `+CASEND` (a trailing `OK` would
be taken by the next `CASTATE?` as an empty list) and `+CAOPEN` before `OK`.
TLS asked for with `CASSLCFG`/`CSSLCFG` is accepted and the same plaintext
services answer.

`+CADATAIND: <cid>` is sent when a connection's buffer goes from empty to
non-empty. A server close is `+CASTATE: <cid>,0` and only once every byte
has been read; `CASTATE?` reports 1 until then. TinyGSM stops reading a
connection that `CASTATE?` reports closed, so a close held back is how the
tail of a response survives (SIM7000SSL.h:532-582).

**The `+CARECV: <cid>,<len>` URC is not sent.** The manual (18.2.6) has no
such URC, and TinyGSM's handler for it (SIM7000SSL.h:636-646) is an
undocumented addition. Without it, a connection that data arrives on is
found only by `maintain()`, which polls through mux 0 alone: TinyGSM's
AllFunctions TLS test opens mux 1 while mux 0's client is closed and reads
0 characters, as it would against a module that follows the manual. The
HTTP, HTTPS, FileDownload and MQTT examples use mux 0 and are unaffected.
The model follows the manual rather than make an unmodelled firmware
behaviour the default.

## Sockets

The CIP stack and the CA stack share the network's eight socket slots (a
slot belongs to the stack that opened it; the CA stack has slots 0 and 1).
A connection is closed by the other end when the server finishes, and
the socket then answers `CLOSED`/`0` until the DUT closes it, and the slot
can be opened again. Losing the bearer ends the connections without their
pending data; the address and port of a connection ended that way read
`0.0.0.0` and 0 in `CIPSTATUS`.

## TinyGSM

TinyGSM 0.12 with `TINY_GSM_MODEM_SIM7000` or `TINY_GSM_MODEM_SIM7000SSL`
works against the model. Its `testAT()` is answered by `AT`, `ATE0` and
`CMEE`; `restart()` by `CFUN=0`, `CFUN=1,1` and `SMS Ready`; `init()`
by `CLTS=1`, `CBATCHK=1`, `CPIN?`; `gprsConnect()` by either command list
above; the downloads by the sockets of the two stacks, a 1 KiB HTTP body
with CRC 0x6f50d767; MQTT, GPS (`CGNSPWR`, `CGNSINF`), `CLBS`, `CNTP`,
`CCLK`, `CBC`, `CUSD`, SMS and `CPOWD` as the table above.

What TinyGSM gets wrong is reproduced, not worked around:

- `+CLBS` carries the longitude first, as above; TinyGSM reads the first
  field as the latitude, so AllFunctions prints the two swapped.
- `CLBS` and `CNTPCID` name SAPBR profile 1, which the SIM7000SSL driver
  never opens; the model locates and syncs on the network, as a module
  with an attached PDP context does.
- SIM7000SSL's AllFunctions sends its TLS request on cid 1, but `maintain()`
  polls `CARECV?` only through cid 0, whose client is already closed: on
  `+CADATAIND: 1` alone the response is never read and the test prints
  `RECEIVED: 0`.
- SIM7000SSL's `gprsConnect()` with both a user and a password sends
  `AT+CNCFG=1,"<apn>","","<user><password>",3`; the examples pass neither.

## Not modelled

PPP, CMUX and `ATD`; single-connection IP mode (`CIPMUX=0`), `CIPRXGET`
modes 0 (push, `+RECEIVE`) and 3 (hex), `CIPACK`, `CIPSERVER`, `CIPSRIP`,
`CIPHEAD`, the transparent mode, `CDNSGIP`, `CDNSCFG`, `CIFSREX`; `CASERVER`,
`CAACK`, the TLS handshake and certificates; the HTTP(S), FTP(S), MQTT and
file-system application commands; `CNMP`, `CMNB`, `CBANDCFG`, `CPSI`; GNSS
beyond power and `CGNSINF` (`CGNSURC`, `CGNSMOD`, `CGNSCFG`, XTRA, SUPL);
incoming SMS and `+CMTI`, text-mode `CMGL`; `+CREG` location fields;
autobauding (`AT+IPR=0`), flow control, PSM and eDRX, sleep and DTR
(`CSCLK` is accepted and does nothing); `;` concatenation other than
`CIFSR;E0`. The clock in `time` does not run, `+CNTP` does not set it, and
the RF sharing between GNSS and LTE is not modelled. Access technology is
always CAT-M (`+COPS ...,7`).

## The DUT image

`test/dut/sim7000/rp2.overlay` puts `uart0` on GP0/GP1 at 115200 with its
RX pulled up, removes the console from it, and aliases it `modem-uart`; no
driver binds it, as Zephyr has none for the SIM7000. PWRKEY is
`pwrkey-gpios` under `/zephyr,user`, GP6 active low, held released by a
GPIO hog from boot. `rp2.conf` turns on the serial driver, interrupt
driven, the ring buffer and CRC. The image takes 24952 bytes of flash and
12440 of RAM. The cases speak AT themselves through `UART modem-uart`,
which writes command lines and raw data and reads what the model sends,
URCs included, from a ring that keeps everything received since boot, and
press PWRKEY through `GPIO pwrkey`; the reference is
`test/rig/dut/README.md`.

```sh
just build-dut cellular/sim7000
METALCLAW_HARNESS_SERIAL=<serial> METALCLAW_ARM_TOOLCHAIN_DIR=<dir> \
METALCLAW_DUT_DEVICE=cellular/sim7000 just test hardware
```

## Tests

`test/cases/test_sim7000.py` runs on the `cellular/sim7000` image and plays
the dialogues of TinyGSM's two SIM7000 drivers through the DUT's UART. It
attaches the model at `uart=(0, 1)` and `pwrkey=6`, writes three names into
`hosts` and a printable 1 KiB `file`, resets the DUT, presses PWRKEY for
1.5 s and checks: `RDY`, `+CFUN: 1`, `+CPIN: READY` and `SMS Ready` after
one boot; the identity (`ATI`, `CGMI`, `CGMM`, `CGMR`, `CGSN`, `GSN`,
`CIMI`, `CCID`, `CPIN?`); `+CEREG?` and `+CSQ` following `registration`
and `rssi`, and the `+CEREG` URC; the CIP stack brought up as TinyGSM does
it (`CIPSHUT`, `CGATT`, `CIPMUX=1`, `CIPQSEND=1`, `CIPRXGET=1`, `CSTT`,
`CIICR`, `CIFSR;E0` answering the model's address); TCP echo of 1 to 256
bytes through `CIPSTART`, a quick-send `CIPSEND`, the `+CIPRXGET: 1` URC,
`CIPRXGET=4` and a manual `CIPRXGET=2` read, intact by CRC, with the
model's counters; an HTTP GET of the file read in 150-byte `CIPRXGET=2`
pieces, intact, the request line recorded and the server's close reported
as `0, CLOSED`; `CONNECT FAIL` for an unknown name and for a closed port;
the CA stack through `CNACT` (`+APP PDP: ACTIVE`, `+CNACT?` with the
address), TCP echo through `CAOPEN`, `CASEND` (its `OK` before `+CASEND`),
`+CADATAIND` and `CARECV`, the same HTTP GET over `CARECV`, and
`+CAOPEN: 1,20` for an unknown name; `CGNSINF` with the receiver off,
without a fix and with three injected fixes field for field; a text-mode
SMS sent and recorded in `sms_outbox`; `CPOWD=1` with `NORMAL POWER DOWN`
and silence after it; and PWRKEY turning the part off and on again.
